## The post template (every post follows this)

This is the structure agreed for post #1 (insulin resistance) — reuse it for all 100:

1. **Hook + problem** — name the symptom/condition, why it's missed.
2. **Statistics people don't know** — "X% have this and don't know it" (the surprise stat). This is the shareable/quotable part.
3. **Signs & symptoms** — scannable bullet list.
4. **The numbers that matter** — which biomarkers/tests reveal it, with reference ranges.
5. **App promo block** — a real Bevita screenshot + how the app surfaces exactly these numbers/trends (like the HOMA-IR "Overall picture" screen in post #1).
6. **What to do** — practical, non-prescriptive steps ("talk to a clinician").
7. **CTA** — "Download Bevita, upload your labs, track it over time." (App Store badge auto-appended by BlogPost layout.)

**Assets:** each post needs a hero/inline screenshot from the app where possible → `public/images/<slug>.jpg`.
**Frontmatter:** `title`, `description` (with the surprise stat), `pubDate`, `heroImage`, `tags`, `author: "Bevita Team"`.
**Internal linking:** every post links to 2–3 sibling posts in the same cluster + the pillar post.

## Daily submission workflow (3/day to Google)

Once the domain is connected and Search Console is verified:

1. Publish the day's 3 posts (they auto-enter `sitemap-0.xml` on deploy).
2. In Search Console → **URL Inspection** → submit each of the 3 URLs → "Request Indexing".
3. Bing Webmaster Tools → **Submit URLs** (Bing allows batch URL submission).
4. Weekly: confirm the sitemap is being read in Search Console → Sitemaps, and check the Coverage/Pages report for indexing status.

**Note:** Google caps manual "Request Indexing" at ~10/day per property — 3/day is well within limits. Bing's IndexNow API can be automated later for instant submission.
